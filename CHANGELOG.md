# shef.problems change log

## 2.0.0 — 2026-09-26

Модуль приведён к канону shef.options: сборка, тесты, CI, Composer,
документация в репозитории. Мажорная версия — из-за несовместимостей ниже.

**Несовместимо с 1.x**

* пакет Composer — `bxshef/problems`, тип `bitrix-module` с
  `installer-name = shef.problems`. Прежний `shef/problems` с типом
  `bitrix-d7-module` развернулся бы в `bitrix/modules/shef.shef.problems/` —
  каталог, которого ядро не знает;
* нужен PHP 8.2 и `shef.options` 3.0.0 и выше;
* от `shef.uiclear` модуль больше не зависит. Пункты «Логи» и «Журналы» с
  верхней панели переехали в штатное меню административной части:
  **Настройки → Учёт проблем** (`admin/menu.php`). Обработчик события
  `shef.uiclear` оставлен заглушкой для обновлённых порталов, деинсталляция
  его снимает;
* **логи переехали за корень сайта** — по умолчанию на уровень выше
  `DOCUMENT_ROOT`, для BitrixVM `/home/bitrix/sh_log`. Старый `/local/sh_log`
  модуль не переносит и не удаляет, а веб-сервер его **по-прежнему отдаёт**:
  перенесите нужное и удалите каталог, поправьте пути в logrotate — см.
  «Как обновиться с 1.x» ниже;
* публичный API: `Constants::getLogPath()` удалён — вместо него
  `getLogDir()`; у `getLogFullPath()` больше нет второго параметра; удалён
  класс `Integration\Shef\UiClear\Manager` вместе с верхней панелью;
* Composer: нужен `monolog/monolog` `^3.10` — проект с Monolog младше не
  соберётся; из `composer.json` убраны `shef/uiclear` и неиспользуемый
  `symfony/options-resolver`; лицензия — MIT вместо proprietary;
* Monolog 2.x в vendor проекта модуль не заменит своей копией и упадёт на
  `Monolog\Level` — проверьте версию до обновления (шаг F в
  [docs/portal-check.md](docs/portal-check.md));
* пример настроек logrotate переехал из каталога модуля в репозиторий,
  `docs/logrotate/`;
* скриншоты документации больше не раскладываются в `/bitrix/images`.

**Как обновиться с 1.x**

1. Обновить `shef.options` до 3.x — до файлов этого модуля: страница
   настроек 1.x с `shef.options` 3.x не открывается, а 2.0.0 со `shef.options`
   2.x не встанет.
2. Заменить каталог модуля целиком (старый убрать, новый распаковать) или
   `composer update bxshef/problems`. Установщик при замене файлов не
   запускается — это и не нужно: страницу логов меню положит само.
3. Перенести нужное из `/local/sh_log` в новый каталог логов и удалить
   `/local/sh_log`; в logrotate заменить пути.
4. Пройти шаг B [docs/portal-check.md](docs/portal-check.md).

**Исправлено**

* страница настроек падала с `shef.options` 3.x: `options_conf.php` передавал
  параметр `indexDoc`, которого больше нет;
* своя копия Monolog обновлена с 3.3.1 до 3.12.0. Старая на PHP 8.4 сыпала
  deprecation из `Monolog\Logger` в лог портала на каждый запрос с логгером;
* `Throwable\TraceRow\Row` читал ключи кадра без проверки — «Undefined array
  key» на каждой записи с трассировкой;
* трассировка начинается с места вызова логгера, где бы ни висел
  `TraceProcessor`: кадры логгера отрезаются по файлам, а не по счёту;
* вывод `PrHandler`, `PrHtmlHandler` и `_pr()` экранируется — раньше данные
  записи шли в страницу как есть;
* **логи вынесены за корень сайта**: по умолчанию на уровень выше
  `DOCUMENT_ROOT`, для BitrixVM — `/home/bitrix/sh_log`; проект может задать
  свой каталог в `/bitrix/.settings_extra.php` (`shef.problems` → `logDir`,
  только абсолютный путь). До 2.0.0 логи лежали в `/local/sh_log`, под корнем
  сайта, и их мог скачать любой;
* `Main\Events::onPageStart` не падает без контекста запроса (агент, CLI);
* установщик берёт файлы из каталога, где модуль стоит на самом деле, а не из
  зашитого `/bitrix/modules`: модуль из `/local/modules` не раскладывал ничего;
* страница просмотра логов `/bitrix/admin/shef_problems_logs.php`, только
  администратору: список файлов и конец файла. Заглушку в `/bitrix/admin`
  установщик пишет с путём туда, где стоит модуль, а удаление снимает только
  свою — файл проекта на её месте остаётся. Ссылка на неё — в меню и на
  странице настроек, вкладка «Сотрудники», там же виден каталог логов. Имя файла проверяется по
  шаблону и после разрешения пути; на портале, обновлённом заменой файлов,
  страницу кладёт меню. Меню больше не ведёт ни прямыми ссылками, ни в
  файловый менеджер;
* важность в журнале событий: CRITICAL, ALERT, EMERGENCY ложились туда как
  UNKNOWN, теперь — ERROR; NOTICE — INFO;
* ID сотрудников из настроек разбираются строго, а не через `(int)`;
* `Utils::getUserBoss()` затирал собственный кеш и читал его без проверки;
* `Logger::getEnumUsedInterface()` не падает на логгере без сервиса;
* `_log1()` создаёт каталог логов, если его нет; `_log()` принимает имя файла —
  сигнатура та же, что у `_log()` из shef.options;
* `include.php` подключает `def-functions.php` до `autoload.php` осознанно, с
  тестом: иначе функции всегда брались бы из shef.options;
* установщик: убрана перекодировка из cp1251 и проверка машины разработчика,
  добавлен отказ на портале не в UTF-8; удаление уносит настройки модуля
  (`savedata = Y` их оставляет) и прибирает каталог `/bitrix/images` от 1.x;
* пример logrotate: `d_size` — не директива logrotate, строка молча
  игнорировалась; теперь `maxsize`;
* сбой записи лога (каталог логов вне `open_basedir`, нет прав) больше не
  роняет вызывающий код: логгеры модуля отдают его в лог PHP строкой
  `shef.problems: запись логгера … не прошла`, а не бросают
  `UnexpectedValueException` в агент или обмен. Касается логгеров из
  `.settings.php` и фабрики проблем; свой `\Monolog\Logger` проекта — как
  настроит проект;
* `Throwable\Manager::buildError()`, `_log()` и `_log1()` пишут трассировку
  без аргументов вызовов — при `zend.exception_ignore_args=Off` в текст
  ошибки и в лог попадали пароли и токены из аргументов;
* фабрика проблем не затирает `moduleId` из контекста записи, если модуль
  ей не задан: в журнал уходило `empty`.

**Добавлено**

* потолок размера для отладочного лога и файлов проблем
  (`Handler\CappedStreamHandler`, 20 МБ, прежний файл — в `<имя>.1`): лог рос
  без предела и забивал диск, даже без logrotate теперь не больше двух
  потолков на файл;
* `Utils::workDateAdd()` — если калькулятор бизнес-процессов упал или вернул
  не дату, прибавляются календарные дни, а не исключение;

* `build.sh` — проверки и воспроизводимый архив; CI на PHP 8.2–8.5,
  `composer validate`, сверка навыков с источником; релиз из `main`;
* тесты: страница настроек против API shef.options 3.x, автозагрузка, `.settings.php`, фронт, трассировка, вывод, журнал
  событий, логгер, настройки, меню, подключение, удаление, своя копия Monolog,
  `composer.json`, документация, примеры, навыки;
* запускаемые примеры в `examples/` — на заглушках и на живом портале;
* `default_option.php`, `CLAUDE.md`, `CONTRIBUTING.md`, документация в `docs/`.
