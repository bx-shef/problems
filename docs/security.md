# Безопасность логов

## Каталог логов лежит под корнем сайта

Модуль пишет в `/local/sh_log` — `\Shef\Problems\Main\Constants::getLogPath()`.
Это под корнем сайта, и **закрывать каталог от веб-сервера — забота проекта**:
модуль сделать этого не может.

Что в логах: трассировки с путями, сообщения исключений, контекст записей —
а в контекст попадают поля заказов, лидов, ответы внешних систем. Открытый
каталог значит, что всё это скачает любой, кто угадал имя файла, а имена
предсказуемы: `log.log`, `sh_problems_sale.log`.

`/local/` в стандартной поставке BitrixVM не закрыт: nginx закрывает
`/bitrix/modules`, `/bitrix/php_interface` и кеши, но не `/local`.

### nginx

В конфигурацию сайта, рядом с остальными `location`:

```nginx
location ^~ /local/sh_log/ {
	deny all;
}
```

### Apache

Файл `/local/sh_log/.htaccess`:

```apache
Require all denied
```

За nginx статические файлы Apache часто вообще не видит — тогда `.htaccess` не
поможет, нужен nginx.

### Проверка

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://портал/local/sh_log/log.log
```

Ожидается `403` (или `404`). `200` — каталог открыт.

## Логи смотреть через админку

Меню **Настройки → Учёт проблем → Логи** открывает файлы через просмотр
файлового менеджера (`fileman_file_view.php`), а не прямой ссылкой. Поэтому
после закрытия каталога меню продолжает работать. До 2.0.0 пункты вели прямо на
`/local/sh_log/*.log` — то есть работали ровно тогда, когда каталог открыт.

Меню видит только администратор.

## Вывод на экран экранируется

`_pr()`, `PrHandler` и `PrHtmlHandler` печатают запись прямо в страницу. Всё,
что пришло из записи, экранируется: в сообщение и контекст попадает в том числе
ввод посетителя, а смотрит на вывод администратор — непроэкранированный вывод
был бы хранимым XSS в его браузере. До 2.0.0 так и было.

Показывать вывод всем (`isShowForAll: true`) — только на стенде: там может
оказаться что угодно из контекста.

## Ключи и токены — не в код

Обработчики с ключами (Telegram, Slack, почта) настраиваются в
`/bitrix/.settings_extra.php`, который не уезжает в репозиторий проекта, — см.
[Monolog](4_monolog.md).
